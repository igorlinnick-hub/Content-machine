# Clips — автомонтаж врачебных дублей

Обновлено: 2026-09-03 · ветка: main

## Состояние

**Область — только телесуфлёр** (решение Игоря 03.09). Дубли, снятые в приложении
(`/api/clips/from-recording` → `processClip`), это единственный путь, который мы
доводим. Файлы из Drive-инбокса (форма МА, загрузки с телефона) сейчас не наша
задача — путь работает как раньше, но им не занимаемся.

**Тракт** (`lib/clips/pipeline.ts`): скачать из Drive → замерить fps и длительность →
вытащить моно-mp3 → WhisperX (Replicate, слова + сегменты) → пасс по дублям (Sonnet,
fail-open) → план резов → `.ass`/`.srt` → **один** проход ffmpeg (резы + кадрирование
1080×1920 + прожиг) → залить в папку клипа на Drive → пуш.

**Главное правило резов (`lib/clips/cuts.ts`):** граница реза может стоять только в
тишине. Якоря — слова из выравнивателя, не сегменты: края сегментов Whisper
приблизительны и regularly залезают внутрь первой/последней фонемы.

- `EDGE_PAD_SEC = 0.3` — тишина, остающаяся с каждой стороны стыка и на голове/хвосте.
- `MIN_CUT_GAP_SEC = 1.0` — пауза короче секунды не режется вообще, это дыхание.
- `MIN_SILENCE_FOR_DROP_SEC = 0.2` — дубль или филлер вырезается, только если тишина
  есть с ОБЕИХ сторон. Нет тишины → рез **не делается** и считается в `refused_count`
  (в логе `clips: N cut(s) refused`). Брак в кадре восстановим, срезанное слово — нет.
- `WORD_GUARD_SEC = 0.05` — граница никогда не подходит к уцелевшему слову ближе.

**Субтитры:** прожиг (`ass.ts`) и `.srt` (`srt.ts`) строятся из одного таймлайна
(`caption-lines.ts`) — те же слова, те же переносы, те же тайминги. Строка не
перекрывает следующую (раньше две реплики накладывались на экране). Без word-таймингов
оба падают на сегментный фолбэк.

**Экспорт:** H.264 High, CRF 18, 30fps CFR, yuv420p, AAC 256k/48k, faststart,
1080×1920 (scale-to-cover + центральный кроп, никаких чёрных полей).

## Последний заход

- Переписан планировщик резов: якоря по словам, границы только в тишине, отказ от
  небезопасного реза вместо его выполнения (`8fcadb6`).
- `caption-lines.ts` — общий таймлайн для прожига и сайдкара.
- **Убран проход `normalizeSource`.** Он перекодировал весь дубль перед тем, как
  cut+burn перекодирует его снова: ~4x реального времени на одном vCPU Hobby, то есть
  в 300-секундный потолок влезало около 70 секунд материала, и обычный двухминутный
  дубль не обрабатывался в принципе. Мусорный тайминг браузерного контейнера чинит не
  лишний проход, а измеренный `-r` на ВХОДЕ — он же работает и на единственном
  оставшемся проходе. Бонусом одно поколение сжатия вместо двух.
- Удалён мёртвый код: `applyCuts`, `burnCaptions`, `burnAssCaptions` — ни одного вызова.
- Проверено: 7 сценариев планировщика + реальный end-to-end энкод (20 с 1280×720,
  пауза вырезана, на выходе 1080×1920 @30fps yuv420p, длительность совпала с планом).

## Сломано / открытые хвосты

- **Не проверено на настоящем MediaRecorder-файле.** Тест гонялся на синтетике с
  честным таймингом. Аргумент, что одиночный проход переживёт мусорный контейнер, тот
  же, на котором работал `normalizeSource` (принудительный `-r` на входе), но это
  рассуждение, а не замер. **Первый прогон — один дубль через Auto-edit, глазами:**
  не поехала ли скорость, совпали ли субтитры со звуком.
- **Реальный потолок лямбды не измерен заново.** Проходов стало вдвое меньше, но
  сколько секунд теперь влезает в 300 с на Hobby — неизвестно. Если длинный дубль
  снова упрётся, вариантов два: `scripts/clips-runner` на маке (см. стеш) или Pro.
- **Стеш `stash@{0}`** — переписанные на «только очередь» `/api/clips/process` и
  `/api/cron/clips-inbox` под несуществующий `scripts/clips-runner`. Запаркованы 03.09:
  очередь без потребителя копила бы строки молча. Вернуть, когда/если будет раннер.
- Пасс по дублям (`retakes.ts`) — Sonnet, fail-open, потолок `MAX_DROP_RATIO = 0.4`.
  Теперь его решение ещё и проходит проверку тишиной, так что ложное срабатывание
  максимум оставит лишнее, а не отрежет слово.
- Whisper-фолбэк на OpenAI даёт слова только при `timestamp_granularities[]=word`;
  если слов нет, режем по сегментам — заметно грубее, но по тому же порогу в секунду.
